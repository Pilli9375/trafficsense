# Reproducibility: a fresh-clone check

Can a stranger who has only the README get this project running and get the same numbers? To
find out, the repository was cloned from GitHub into an empty folder, a new Python environment
was built from the README alone (not the project's own checkout or environment), and every
deterministic result was run again and compared with the committed files. Each gap found was
fixed in the repository, and the affected steps were then run again in the same clone.

All tables below are generated by `python scripts/make_reproducibility.py` from
`outputs/reproducibility/fresh_clone.json`, which keeps the raw values of every comparison
(`--check` fails if this document and that file disagree). The README's setup numbers (disk
space, install times, CPU fallback) are tagged against the same file.

**What this shows.** Everything that does not depend on lane changing or the LLM server is
exactly repeatable, and every one of those committed numbers was reproduced to the last digit:
the 42 runs behind the headline tables (FixedTime, Webster, MaxPressure, preemption), the
default-setting validation runs, the IDD label conversion, the detector's test-split
evaluation including the whole camera error model, and the dashboard's 9 replays (their files
are byte-identical to the originals).

Two parts are not exactly repeatable, and this check measured how much they vary:

* **CityFlow with lane changing on.** Only the validation runs that copy CoLLMLight's settings
  use it. Plain CityFlow, with nothing of ours involved, gives a different average travel time
  when the same run is repeated (table below); with lane changing off it never does. Throughput
  and CoLLMLight's queue length never changed. This corrects an earlier explanation in
  [`validation.md`](validation.md), which put the small differences down to which read-only
  queries are made between steps.
* **LLM answers from Ollama on a GPU.** The project's earlier observation stands (decision logs
  of the Jinan seeds split early; a manual short re-run differed in a few answers, see
  [`results.md`](results.md)). In this check, though, the 600 s run of the pre-registered arm
  repeated exactly: all 121 answers were the same text and every metric matched. One identical
  run does not make the server deterministic; every LLM run's decisions are logged so it can be
  replayed exactly.

### Gaps found, and what was changed

| Gap (a stranger following the README would hit it) | Fix |
|---|---|
| `pytest -q` failed after the README's install: three detector tests import `torch`, which only the `perception` extra installs. | They skip without it (`pytest.importorskip` inside the test). |
| `make_report.py --check` failed: the README badge counts collected tests, and the browser tests were collected only when Playwright was installed. | Optional-extra tests skip at run time, so every install collects the same tests. |
| `make_results`, `make_camera_error` and `make_model_size --check` reported every committed run as missing: a run counted as complete only with its `metrics.csv`, which is gitignored. | `summary.json` (written last) alone marks a complete run; the set of runs in the project checkout is unchanged. |
| The README's LLM command ran fine but then exited with an error, because the committed run of the same arm and model made the report step refuse two runs. | `benchmark_llm.py --out outputs/runs` makes a trial run that leaves the benchmark files alone; the README uses it. |
| `pip install -e ".[…,perception]"` installs PyPI's PyTorch, built for CUDA 13; this GPU driver supports CUDA 12.9 at most, so the GPU would not be used. | README installs the CUDA 12.6 build first, as the project's environment had it. |
| No versions were pinned; a fresh install already got a newer `ultralytics` than the one the results were made with. | `requirements-lock.txt` (pip constraints) with the project's exact versions; CityFlow pinned to commit `81ee0f4`. |
| `eval_detector.py` read the weights from the absolute path recorded on the training machine, so it failed elsewhere and, in a clone on the same machine, silently reused the original run's cached detections. | Weights come from `paths.detector_runs` in the config and must match the recorded sha256. |
| The dashboard's replays are not in git and making them needed a symlink the README never showed. | `scripts/build_replays.py` makes them from the committed runs in one command; the README lists the symlinks. |
| WSL could only reach the Windows Ollama app because `networkingMode=mirrored` is set in `.wslconfig`; the README only showed the Linux installer. | README describes both ways. |
| Hardware and disk needs, and what works without a GPU, were not stated. | README "Requirements" table, measured here. |
| `make_camera_error.py --check` passed only when the clone sat where the runs were made: the runs recorded the error model's absolute path, which the script made repo-relative against the current folder. (Hidden at first, because the check had already failed on the missing `metrics.csv`.) | The path comes from `paths.camera_error_model`; the recorded one must end with it. |
| The browser layout tests failed in a clone on a Windows drive: they waited for Streamlit's "running" indicator, which on a slow first run appears only after they had looked, so a card was measured before its chart existed. | They wait for Streamlit's own script state to be `notRunning`, then for every chart to be drawn. |
| `docs/validation.md` called the 15 s MaxPressure "now" the default; the default changed later. | Wording fixed; `run_matched.py --profile default_maxpressure_15s` reproduces those rows. |

## Not repeatable, and why

* **LLM answers** (Ollama on a GPU). Not guaranteed to repeat at temperature 0; every
  decision is logged in the run's `decisions.jsonl`, the replays are made from those logs and
  are kept only if they reproduce the run's metrics.
* **CityFlow with lane changing on** (validation's matched runs only). Small run-to-run
  variation inside CityFlow, measured above. All experiments use lane changing off.
* **The hosted model** of the exploratory model-size study needs an API key and depends on the
  provider; it was not re-run here.
* **Detector training** (13 hours on this GPU) was not re-run; GPU training is not
  bit-for-bit deterministic in general. The weights' sha256 ties every result to one file.
* **Times** depend on the machine and the disk.
